# gosling v1.2.4

## Summary

gosling v1.2.4 collects the source changes since
[`v1.2.2`](https://github.com/cephalopod-ai/gosling/releases/tag/v1.2.2)
(2026-09-08), the last published GitHub release. It supersedes the `v1.2.3`
source candidate, which was prepared in the version manifests but never
tagged or published; the [v1.2.3 notes](v1.2.3.md) are retained as a
point-in-time record of that candidate. This release adds budget-capped
auto-compaction, closes two reliability gaps found by an internal audit pass
of the day's own changes, and improves permission and error messaging.

## Highlights

- **Budget-capped auto-compaction.** A new `autoCompactReduction` preference
  lets compaction target a lower usage budget instead of always collapsing to
  the full eligible region, and an invalid threshold/reduction value now
  degrades auto-compaction with a warning instead of failing every
  subsequent turn.
- **Atomic compaction writes.** Conversation replacement and session usage
  metrics now commit in a single transaction, so a crash between the two can
  no longer leave stale, over-threshold token counts that spuriously
  re-trigger compaction on the next turn.
- **Output-revision restore integrity.** Restoring a saved output revision
  now detects an interrupted write (DB history committed before the file
  swap completed) instead of silently trusting a history row the filesystem
  never reflected.
- **Structured tool-denial and policy messaging**, and a corrected
  distinction between a session losing its turn lease and the user
  cancelling a turn, so terminal errors are reported accurately instead of
  masked as a generic cancellation.
- **Desktop artifact management**: Trash/delete for artifact files, a
  **Copy contents** authorization boundary, file timestamps, an Outputs
  repository-file filter, a workspace-readiness indicator in navigation, and
  shared `Z_INDEX` layering across dialogs, dropdowns, and tooltips.
- **Working-directory scope and permission-prompt readability** refinements,
  including expanded regression coverage for the scope inspector.

## Compaction and context management

- `autoCompactReduction` (an ACP preference alongside `autoCompactThreshold`)
  targets `threshold - reduction` instead of always collapsing the full
  eligible region, so a session under moderate pressure keeps more history.
- `check_if_compaction_needed` now treats an invalid threshold or reduction
  value (a bad config file or env var, not just the literal disabled value)
  as "auto-compaction disabled" with a one-time warning, rather than failing
  every subsequent `reply()` call for the life of the process. Preferences
  written through the ACP preferences API are still rejected at write time.
- `replace_conversation` and the session's usage-metrics update now commit
  together as `replace_conversation_and_record_usage`. Previously these were
  two independent writes; an interruption between them left `total_tokens`
  stale-high, which the context-usage heuristic then preferred over the
  correct post-compaction estimate, silently re-triggering an unnecessary
  compaction pass.
- `restore_output_revision` now detects the case where its history commit
  landed but the corresponding file swap did not complete, mirroring the
  self-healing reconciliation the sibling output-capture path already had.

## Permissions, errors, and reliability

- Tool denials now carry structured, policy-aware messaging (for example,
  `Tool denied by policy: User permission denies this tool`) instead of a
  generic denial string.
- Session-lease loss and user-initiated cancellation are now reported as
  distinct terminal outcomes; a lease lost to another owner no longer reads
  as if the user cancelled the turn, and CLI cancellation/EOF handling shares
  cleanup exactly once instead of emitting duplicate notices.
- The working-directory scope inspector gained expanded regression coverage
  from an internal audit pass; its temp-directory scratch exemption (added to
  reduce prompt fatigue for ordinary temp-file use) was found to be host-wide
  rather than session-scoped and is tracked as a follow-up rather than
  changed in this release, since narrowing it is a deliberate design
  decision for the release owner rather than an automated patch.

## Desktop

- **Trash and recovery**: artifact files can be deleted to the system Trash
  from the Desktop UI, with recovery through the OS Trash as usual.
- **Copy contents**: an authorization boundary gates the existing Copy
  contents action; the concurrent-modification guard now also checks file
  identity (`ctimeMs`), not size and modification time alone.
- **File timestamps**: Outputs and Library rows show filesystem creation and
  modification times in the local timezone.
- **Repository file filtering**: the Outputs pane's **Hide repository files**
  switch (added in v1.2.2) persists its setting and filter behavior.
- **Workspace readiness**: the navigation panel shows workspace readiness
  status.
- **Shared `Z_INDEX` layering**: dialogs, dropdowns, tooltips, and popovers
  now stack from one shared constant registry instead of ad hoc per-component
  values; `Select`'s popover menu was migrated onto the same registry during
  this release's own audit pass.

## Internal audit and playtest hardening

This release's own changes received an internal audit pass across data
flow, workflow/UI, reliability, and architecture-drift lenses, plus
negative-space, invariant-sync, resource-lifecycle, and recovery-idempotency
lenses, and a playtest pass against the day's new Desktop surfaces. Ten
findings from the first pass and six from the second were repaired and
validated. Preparing this release also found that a genuine, unrelated
behavior change in the day's own reliability work (a denied or cancelled
tool call now correctly makes a follow-up completion call reporting the
decline, instead of ending the turn silently) had broken several ACP
provider/server test fixtures that assumed the old behavior; those fixtures
are repaired, and the shared `OpenAiFixture` test helper's request matcher
is now order-independent so it doesn't race a pre-existing background
tool-call-summary request. See
[`docs/cloud/2026-09-08-evening-audit-repair.md`](https://github.com/cephalopod-ai/gosling/blob/main/docs/cloud/2026-09-08-evening-audit-repair.md)
and
[`docs/cloud/2026-09-08-cross-cutting-lens-audit.md`](https://github.com/cephalopod-ai/gosling/blob/main/docs/cloud/2026-09-08-cross-cutting-lens-audit.md)
for the full findings and repair evidence, and
[`docs/cloud/2026-09-08-desktop-surfaces-playtest.md`](https://github.com/cephalopod-ai/gosling/blob/main/docs/cloud/2026-09-08-desktop-surfaces-playtest.md)
for the playtest results and seven new scenario cards added to
`docs/test_scenarios/`. Security was explicitly out of scope for these
passes; no security review is claimed by this release.

## Compatibility and breaking changes

- No schema migration, provider contract change, or removed capability is
  introduced by this release. The `workspaceFolderRoots` and
  `autoCompactReduction` additions are backward compatible; an older server
  or client that does not send/read them behaves as before.
- A complete compatibility review across every provider and extension
  surface was not performed. Do not infer from these notes alone that no
  other breaking change exists.

## Known issues

- The temp-directory scratch exemption in the working-directory scope
  inspector is host-wide rather than session-scoped (see "Permissions,
  errors, and reliability" above); narrowing it needs an explicit release-
  owner decision and is not made in this release.
- The maintainer-owned installed-Desktop, signing, artifact, and clean-
  machine checklist gates in `RELEASE_CHECKLIST.md` are not claimed complete
  at publication time.
