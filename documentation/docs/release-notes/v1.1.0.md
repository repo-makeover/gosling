# gosling v1.1.0

> **Superseded and never published.** `v1.1.0` was prepared in the source
> manifests but no `v1.1.0` tag or GitHub release was ever created. The changes
> described here shipped in [v1.2.1](v1.2.1.md). This page is retained as a
> point-in-time record of the unpublished candidate; it does not describe any
> published artifact.

## Summary

This candidate collects the changes since
[`v1.0.1-optimization-and-workspaces`](https://github.com/cephalopod-ai/gosling/compare/v1.0.1-optimization-and-workspaces...main), including Desktop shell work, session and artifact handling, provider support, and audit-driven reliability and security repairs.

## Highlights

- The Desktop shell gained project-session and output-library work, lifecycle
  acceptance automation, and fixes for the New Chat flow and workspace-less
  session artifacts.
- Session storage was split into focused modules for schema/migrations, pool
  lifecycle, message and summary storage, artifact inventory, library storage,
  session CRUD, transfer, and listing/pagination.
- The CLI gained localized session-history search, session input/output plumbing,
  and a `secret` command.
- Mistral Vibe is available through ACP, and replayed Mistral reasoning content
  is omitted to avoid provider 422 errors.
- Desktop chat now shows a Git branch indicator for the selected working
  directory and provides a recent-model picker with the five latest successful
  model/provider selections.
- Autonomous mode is the low-interruption default. Ordinary provider-native
  tools proceed without per-command prompts, while explicit security warnings
  retain a human gate. Durable **Always Allow** decisions survive app restarts,
  sessions, and threads.
- Deep Research accepts traditional Office, PDF/PostScript, text/data, and
  image inputs with content validation and bounded extraction. Follow-up turns
  no longer fail merely because a previously completed research session did
  not create a new report on every conversational response or re-mentioned an
  older output path.
- Backend-owned session deliverables regain transient exact-file preview
  capabilities, so restarting the app or using a session workspace outside the
  app's launch folder does not require selecting the file again.
- Streamable HTTP MCP extensions accept pre-registered OAuth client settings:
  `client_id`, `client_secret_key`, and `scopes`. Client secrets remain
  references to the environment or gosling secret store, not inline values.

## Reliability and security

- Tool-approval, egress-inspection, credential, configuration, session-recovery,
  CSP, and MCP-app handling received targeted repairs and regression coverage.
- Legacy session import retries and reports skipped entries, while long-running
  reads, probes, and caches have explicit bounds.
- Repository-sourced agent files cannot grant themselves extensions.
- Obsolete TagTeam provider, session, and UI support was removed. Delegation
  continues through the maintained Summon and ACP paths.
- Release-readiness repairs corrected Desktop research-input filtering, shell
  package smoke-test binary/version discovery, the Cargo Deny RSA dependency
  path, and the health-dashboard workflow token source.

## Documentation

- Release documentation now records `v1.1.0` as the candidate and preserves the
  prior noncanonical release tag as historical evidence.
- The version-bump recipe now resolves its version surfaces from the justfile
  location and checks them before changing a manifest.
- The source-grounded [Goose v1.47 compatibility guide](../guides/goose-v1-47-compatibility.md)
  records the scope and limits of the three imported compatibility features.

## Validation

- Desktop typecheck and 1,074 tests passed on 2026-08-28. The repaired shell
  runtime integration suite also passed 15/15 after its release-version and
  binary-discovery fixtures were corrected.
- The documentation test suite, TypeScript typecheck, and production build
  passed on 2026-08-28.
- The complete Rust workspace suite passed on 2026-08-28. The Deep Research
  completion verifier passed 7/7 focused tests, and workspace Clippy passed
  with warnings denied.
- A production Apple Silicon package was built, ad-hoc signature-verified,
  installed, and relaunched through the local backend startup. Its embedded
  sidecar is byte-identical to the release-profile binary. ScreenCaptureKit
  prevented an automated side-panel click-through, so that visual check remains
  partial; local packaging is not a replacement for the signed/notarized
  release-artifact acceptance gate.
- Remaining candidate validation is tracked in
  [`RELEASE_CHECKLIST.md`](https://github.com/cephalopod-ai/gosling/blob/main/RELEASE_CHECKLIST.md); no signed artifact,
  packaged Desktop acceptance, GitHub-release readback, or publication claim is
  made by these notes.

## Compatibility and breaking changes

Compatibility review is not complete. Do not infer that no breaking changes
exist from this candidate note alone.

## Known issues

- The release requires all remaining checklist gates, including a clean or
  isolated macOS Apple Silicon installation and GitHub readiness, before
  tagging.
- The GitHub `signing` environment currently exposes none of the Apple or Azure
  signing credentials referenced by the tag workflow. A signed release cannot
  be published until those credentials are provisioned; the release workflow
  must not be weakened to bypass that gate.
- The previous stable release tag is noncanonical. It is preserved and is not
  moved or recreated.
