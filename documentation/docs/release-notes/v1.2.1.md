# gosling v1.2.1

## Summary

gosling v1.2.1 is the first published release since
[`v1.0.1-optimization-and-workspaces`](https://github.com/cephalopod-ai/gosling/releases/tag/v1.0.1-optimization-and-workspaces)
(2026-07-23). It collects more than 440 commits of provider work, Deep Research,
permission and security repairs, Desktop features, MCP extension fixes, measured
performance work, and a large behavior-preserving modularization campaign.

Two earlier candidate versions, `1.1.0` and `1.2.0`, were prepared in the source
manifests but never tagged or published. This release supersedes both. The
[v1.1.0 candidate notes](v1.1.0.md) are retained as a point-in-time record of
that unpublished candidate and are not a description of any published artifact.

## Highlights

- **Autonomous mode is the low-interruption default.** Ordinary provider-native
  tools proceed without per-command prompts, while explicit security findings
  keep a human gate. Durable **Always Allow** decisions survive app restarts,
  sessions, and threads.
- **Deep Research completes unattended.** The completion gate closes out the
  dual-destination contract itself, verifies Research Library copies by content
  rather than by claim, and accepts Office, PDF/PostScript, text/data, and image
  inputs with content validation and bounded extraction.
- **New provider coverage**, including a Claude Code provider, Antigravity, and
  refreshed model catalogs, plus safe turn-level provider failover.
- **Desktop workspaces, credential profiles, and an artifact workbench** for
  session outputs, with a research model team selector and initial-input dialog.
- **Measured performance work** on chat-list snippets, session listing, and
  durable tool dispatch.
- **A behavior-preserving modularization campaign** across the agent, ACP
  server, extension manager, session manager, and Desktop main process.

## Providers and model access

- A Claude Code provider is available, with refined action-required handling for
  its control requests. Its `AskUserQuestion` control request now renders as a
  form elicitation in every mode instead of a bare tool-approval card.
- Antigravity provider support was added to the canonical catalog and
  configuration.
- Turn-level provider failover retries a failed turn against a configured
  alternate without corrupting conversation state.
- OpenAI format handling gained request/response overrides and model metadata;
  the OpenAI-compatible streaming decoder deserializes each event once.
- Provider API clients accept configurable read timeouts.
- Provider authentication, OAuth, GCP, and Snowflake paths received targeted
  repairs.
- Mistral Vibe is available through ACP, and replayed Mistral reasoning content
  is omitted to avoid provider 422 errors.

## Deep Research

- Research turns complete without operator involvement: the completion gate
  mirrors a missing dual-destination copy itself, records what it did, and
  announces it inline.
- Research Library copies made outside the structured file tools are discovered
  by a bounded library scan and verified by SHA-256, placement, and run window.
- Report links in a final message resolve against the session's granted folders,
  with output roots first and the library last, so reports written to Outputs or
  the library are no longer dropped or reported as phantom paths.
- Traditional Office, PDF/PostScript, text/data, and image inputs are accepted
  with content validation and bounded extraction.
- Follow-up turns no longer fail merely because a completed research session did
  not produce a new report on every conversational response.
- A research session resumed from history or after a restart keeps its research
  identity, because session metadata now carries the research library path.

## Permissions and security

- Tool approval, egress inspection, credential handling, configuration,
  session recovery, Content Security Policy, and MCP-app handling received
  targeted repairs and regression coverage.
- Session transfers are egress-inspected, and session transfer is
  permission-aware.
- Sessions can be granted private directories, and a working-directory scope
  inspector enforces the session's pinned filesystem boundary.
- The working-directory scope inspector no longer treats device streams such as
  `/dev/null` as out-of-scope writes, splits shell commands at glued separators
  so each simple command is judged on its own, and recognizes common read-only
  diagnostics. Writes hidden inside a program argument are now detected, which
  the previous token check missed.
- Repository-sourced agent files cannot grant themselves extensions.
- Backend process handling and URL security were hardened, and legacy session
  import retries and reports skipped entries.
- Tool dispatch again resolves an owner-prefixed name such as
  `code_execution__list_functions` against a live extension. Platform extensions
  advertise their tools unprefixed, and a change earlier in this range dropped
  that fallback, so a model addressing a platform tool by owner failed its turn.
  A prefix naming no extension still fails.

## Desktop

- Workspaces, credential profiles, and an artifact workbench for session outputs.
- A research model team selector and a research session initial-input dialog.
- A settings view, updated navigation, a Git branch indicator for the selected
  working directory, and a recent-model picker.
- Session input controls for artifact panes, session artifact inventory, and
  output file extension settings.
- Markdown rendering improvements, including ChatGPT-style math delimiters.
- User-facing and progressive messages are localized.
- Backend-owned session deliverables keep transient exact-file preview
  capability across restarts and out-of-launch-folder workspaces.

## CLI and ACP

- ACP elicitation messages are plumbed through the provider and server with
  schema-driven forms, reaching the CLI session UI.
- The CLI gained localized session-history search, session input/output
  plumbing, and a `secret` command.
- Session manager support was added across ACP providers.

## MCP extensions

- Streamable HTTP SSE streams stay alive past the extension timeout. The
  request timeout previously bounded the whole request including the long-lived
  SSE body, tearing the stream down at an exact timeout cadence and taking
  in-flight requests with it.
- Streamable HTTP extensions accept pre-registered OAuth client settings:
  `client_id`, `client_secret_key`, and `scopes`. Client secrets remain
  references to the environment or gosling secret store, not inline values.
- An extension secret can be resolved from a named OS keychain item, and
  `secret_sources` entries resolve one at a time so one failure does not mask
  the others.
- Accumulated MCP configuration temp files are swept.

## Performance

Each item below was measured before and after on the same local harness. These
are local debug-build fixtures, not production or release-build latency claims.

- Chat-list snippets borrow visible text and stop at known truncation instead of
  normalizing whole messages. A 20-session list fixture fell from 149.93 ms to
  31.26 ms.
- Session listing derives each session's newest message time from index-range
  maxima instead of aggregating a join over every message row, and the paged
  path counts messages only for the returned page. A 300-session by
  100-message fixture fell from 36.06 ms to 2.14 ms for the first page.
- Durable tool dispatch checks the newest checkpointed copy of a tool request,
  so the scan stops at the most recent message instead of parsing every message
  in the session under the write lock. A 300-round fixture fell from 7.89 ms to
  0.19 ms per dispatch.
- Earlier in this range, chat recall, message ordering, replay-buffer
  accounting, reply telemetry, and the Desktop message-list render index each
  received measured repairs.

## Internal structure

A behavior-preserving modularization campaign split the largest source files
into focused modules with no intended behavior change: the agent, the ACP
server, the extension manager, the session manager, and the Desktop main
process. Each campaign carried a pre-edit validation baseline and a closing
audit recorded under `docs/logs/session/`.

## Removals

- TagTeam provider, session, and UI support was removed. Delegation continues
  through the maintained Summon and ACP paths.
- Obsolete agent code and retired release automation were removed. Patch
  releases require an explicit reviewed branch or commit and tag; there is no
  automatic next-patch branch.

## Documentation

- Release documentation records `v1.2.1` as the published version and preserves
  the noncanonical `v1.0.1-optimization-and-workspaces` tag as historical
  evidence rather than retagging it.
- The source-grounded [Goose v1.47 compatibility guide](../guides/goose-v1-47-compatibility.md)
  records the scope and limits of the imported compatibility features.
- Autonomous permission recovery, the deep research walkthrough, the audit and
  repair campaigns, and the modularization campaigns are recorded under
  `docs/logs/session/`.

## Validation

Observed on 2026-09-06 from the release tree on macOS 26.6.2, Apple Silicon,
Rust 1.92.0:

- `cargo fmt --all -- --check` passed.
- `cargo clippy --all-targets -- -D warnings` passed.
- The repository's CI test gate passed, run as CI runs it from `crates/`:
  `cargo test -- --skip scenario_tests::scenarios::tests` followed by
  `cargo test --jobs 1 scenario_tests::scenarios::tests`. On a developer machine
  that has its own gosling config, two compaction tests and one preferences test
  read that real config instead of the defaults they assert against; they pass in
  CI, which has none. That test-isolation defect is tracked as REL-CI-002 and is
  not a product regression. CI is the authority for this gate.
- `cargo test -p gosling --features code-mode --test acp_provider_test` passed
  13 tests, including `test_prompt_codemode`.
- `pnpm run typecheck` passed in `ui/desktop`.
- `pnpm test` passed in `ui/desktop`: 150 test files, 1,140 tests.

Preparing this release found that the repository's CI test gate had been failing
on `main` since 2026-09-05, on `test_prompt_codemode`, caused by the dropped
tool-dispatch fallback described above. That defect is fixed in this release and
the gate is green again.

These are source-tree checks. They are not a substitute for the installed
Desktop, signing, notarization, updater, and clean-machine gates in
[`RELEASE_CHECKLIST.md`](https://github.com/cephalopod-ai/gosling/blob/main/RELEASE_CHECKLIST.md),
which remain maintainer-owned and are not claimed here. No signed artifact,
packaged Desktop acceptance, or clean-machine installation result is asserted by
these notes; read the published artifacts and their checksums back from the
GitHub release before relying on them.

## Compatibility and breaking changes

- TagTeam provider, session, and UI support is removed. Configurations that
  referenced TagTeam must move to Summon or ACP delegation.
- Session storage schema migrations run automatically on first open. Sessions
  created by this version are not expected to be readable by v1.0.1.
- A complete compatibility review across every provider and extension surface
  was not performed. Do not infer from these notes alone that no other breaking
  change exists.

## Known issues

- The maintainer-owned installed-Desktop, signing, artifact, and clean-machine
  checklist gates are not complete at publication time and are tracked in
  `RELEASE_CHECKLIST.md`.
- The GitHub `signing` environment must expose the Apple and Azure signing
  credentials the tag workflow references before a signed artifact can be
  produced. The release workflow must not be weakened to bypass that gate.
- The previous stable release tag is noncanonical. It is preserved and is not
  moved or recreated.
- Native macOS auto-update remains disabled until a compatible shipped version
  and updater metadata make promotion safe.
